# Hover-text catalog: every explanation the page can show

> This file is generated by `tools/clrs_docs_generate.py` from the repository and the training outputs; do not edit it by hand. Re-run the generator after any change to the data.


The page explains its own vocabulary in hover cards (`explain.js`). Each card has up to four parts: **what it is**, **why it is there**, and **how to read it / a technical note**. The shared table `GL` is used by both pages; the table `GL_EDGE` overrides entries on the main page (edge-site transcoders) and is ignored on `/demo`.

Besides these fixed entries the page builds dynamic cards for graph nodes (`node:`), table cells (`cell:`), attribution nodes and edges (`an:`, `ae:`), feature labels (`fl:`) and dynamic values (`dyn:`).

## Shared entries (used on `/demo`, and on the main page where not overridden)

### `algo`: Algorithm

- **What it is:** Which of the 12 CLRS-30 graph algorithms to trace. Each has its own separately trained 128-hidden MPNN checkpoint and its own transcoder.
- **Why it is there:** Different algorithms need different internal state (reachability, colours, distances…), so comparing their circuits shows what the same architecture learns for each.
- **Technical note:** Tag after the name: target type and whether the model generalises (CLEAN) or breaks (SEVERE) on bigger graphs.

### `all`: All

- **What it is:** Shows the strongest edges of the full linearised computation (up to 6,000, by |weight|), unpruned.
- **Why it is there:** Use it to check that pruning did not hide something important.

### `attrgraph`: Attribution graph

- **What it is:** A graph of direct linear effects that explains one prediction. Columns are the graph’s nodes, rows are algorithm steps (newest at the top). Each step has a row of transcoder features (circles, one set per graph node) and a row of encoder leaves (squares: the inputs and fed-back hints read at that step). Edges cross columns because every node receives messages from every other node. The window covers the last 3 steps; older state enters as one leaf per node.
- **Why it is there:** This is the method of Ameisen et al., “Circuit Tracing: Revealing Computational Graphs in Language Models”, Anthropic 2025, used in Lindsey et al., “On the Biology of a Large Language Model”, Anthropic 2025 to trace multi-step reasoning. Here it is applied to a graph neural network executing a textbook algorithm.
- **Technical note:** To make the model linear for one input, the top-k feature choice is frozen at its actual value (the paper freezes attention patterns and normalisation denominators for the same reason). Edge = source activation × (source’s decoder vector · the gradient of the destination).

### `avAct`: Activation

- **What it is:** The feature’s value at this node and step (after ReLU and top-k).

### `avError`: Error node

- **What it is:** The part of a node’s new hidden state that the transcoder did not reconstruct. Adding it back makes the replacement model reproduce the real network exactly (Circuit Tracing).
- **Why it is there:** Its outgoing weight shows how much of the mechanism lies outside the features.

### `avInfluence`: Influence on targets

- **What it is:** How much of the targets’ (probability-weighted) inputs flow through this node, counting all paths: the quantity used to prune the graph (Circuit Tracing’s influence).
- **Why it is there:** The pinned feature at load time is the most influential one.

### `avRowF`: Features at this step

- **What it is:** For every graph node, the transcoder features active at its node update in this step (≤8 each), coloured by the predicate that best describes them. The hatched square beside them is that node’s error node.
- **Why it is there:** Features are the interpretable units the explanation is written in.
- **Technical note:** Size ∝ √activation.

### `avRowL`: Leaves at this step

- **What it is:** The values the encoders read at this step, per node: inputs (pos, A, adj, s…) and hints the model fed back from its previous prediction; edge-located values (A[i,j]) sit under the first node of the pair.
- **Why it is there:** Leaves are where the explanation stops.

### `avRowO`: Predictions of this step

- **What it is:** The target logits being explained: the algorithm’s main hint for the selected node at the next step, and (for algorithms with a parent pointer) its pointer prediction. Filled chips are the model’s top choice.
- **Why it is there:** Every path in the graph ends at one of these.

### `avTotalEffect`: Total effect

- **What it is:** Change in each target logit per unit change of this feature’s activation, summed over every path in the frozen-linear graph (direct and indirect).
- **Why it is there:** This is what an intervention on the feature should do, if the linear picture is right.

### `avg_class`: Class-change feature

- **What it is:** Best described by a categorical transition of the target hint (e.g. “becomes class 1” = turns grey in DFS).

### `avg_neg`: Negated-state feature

- **What it is:** Best described by the absence of a state (“not stays 0” fires on every node that is not staying unreached, …).

### `avg_none`: Unlabelled feature

- **What it is:** No predicate describes it well, or it is too rare to name. It can still carry real influence.

### `avg_source`: Source feature

- **What it is:** Fires on (or tracks) the start node.
- **Why it is there:** Algorithms that start from a source need a stable “I am the source” signal.

### `avg_state`: Target-state feature

- **What it is:** Best described by a predicate on the target hint itself: newly/still reached, distance increases/decreases/stays, etc.

### `bias`: bias

- **What it is:** The decoder’s constant term: what the prediction would be with every feature and leaf at zero.
- **Why it is there:** Included so the edges into the target add up exactly to the logit being explained.

### `bynode`: By node

- **What it is:** Every feature appears once per graph node and step where it is active: column = graph node, row = step. Its label (e.g. f37) is the transcoder feature index.
- **Why it is there:** Keeps full detail: you see exactly when and at which node each feature fired.

### `cleanSevere`: CLEAN / SEVERE

- **What it is:** Based on the gap between the validation score (16-node graphs) and the out-of-distribution test score (64-node graphs). CLEAN models keep most of their accuracy (gap ≤ 0.074); SEVERE ones lose a lot (gap ≥ 0.46).
- **Why it is there:** CLRS’s central question is whether a model learned the algorithm or a size-specific shortcut. A circuit from a SEVERE model may explain a shortcut, not the algorithm.
- **Technical note:** Source: Veličković et al., “The CLRS Algorithmic Reasoning Benchmark”, ICML 2022; numbers from this project’s results_v3/summary_v3.json.

### `f1`: F1

- **What it is:** Harmonic mean of precision and recall: 2PR / (P + R).
- **Why it is there:** A single number for how well the label describes the feature.

### `featdetail`: Feature detail

- **What it is:** Everything known about the clicked feature: its label and scores, its edges in this graph, and real dataset examples where it fires most strongly.
- **Why it is there:** Following the paper, a feature is interpreted from its top-activating examples as well as its label.

### `featlabels`: Feature labels

- **What it is:** Each transcoder feature is scored against hand-written predicates on the true hints (e.g. “newly 1” = this node became reached this step).
- **Why it is there:** Labels turn feature indices into readable meanings. The score tells you how much to trust a label; a low-F1 label is a guess.
- **Technical note:** P = precision, R = recall, F1 = their harmonic mean, over a fixed labelling dataset.

### `firesOn`: Fires on

- **What it is:** How many (node, step) sites in the labelling dataset activate this feature, out of all sites.
- **Why it is there:** Very rare features get the label “(rare)” because there is too little data to name them reliably.

### `fvu`: Transcoder FVU

- **What it is:** Fraction of variance unexplained: how much of the real 128-number update the transcoder fails to reconstruct (0 = perfect).
- **Why it is there:** The attribution graph explains the transcoder’s version of the model (the “replacement model”). The lower the FVU, the more faithful that explanation is to the real network.
- **Technical note:** FVU = ‖h − ĥ‖² / ‖h − mean(h)‖² on held-out data.

### `hidden`: hidden_dim = 128

- **What it is:** Every node carries a 128-number state vector. It is NOT 128 layers: the MPNN has one processor whose weights are reused at every algorithm step, like the body of a loop.
- **Why it is there:** This vector is where the model stores what it has worked out so far (reached? distance? colour?), mixed together across many dimensions. Decoding it is the point of the transcoder.
- **Technical note:** CLRS “MPNN” processor: m_ij = MLP(relu(W₁z_i + W₂z_j + W_e e_ij + W_g g)), aggregated by a max over ALL nodes (the processor is fully connected; the graph’s edges enter only as edge features), then h′ = LayerNorm(relu(O₁z + O₂m)).

### `howItWorks`: How this tool works

- **What it is:** 1) CLRS samples a graph and runs the textbook algorithm to get hints. 2) The trained MPNN executes the same algorithm step by step. 3) A transcoder rewrites each step’s node update as a few interpretable features. 4) Freezing which features are active makes one prediction a linear sum, shown as an attribution graph. 5) Clamping features checks that the graph is causally right.
- **Why it is there:** Accuracy says whether the model is right; this says how it gets there, and interventions say whether that story is true.
- **Technical note:** Method: Ameisen et al., “Circuit Tracing: Revealing Computational Graphs in Language Models”, Anthropic 2025 / Lindsey et al., “On the Biology of a Large Language Model”, Anthropic 2025. Benchmark: Veličković et al., “The CLRS Algorithmic Reasoning Benchmark”, ICML 2022.

### `inBrowser`: In-browser model

- **What it is:** The trained 128-hidden network runs inside your browser (a JavaScript port of the CLRS encoders, processor and hint decoders, checked against the original JAX model on all 12 algorithms to ~1e-4). The server only samples the graph.
- **Why it is there:** Removes the network round trip for the heavy part, so changes to n, p and seed appear almost instantly.
- **Technical note:** Until the weight bundle (1–2 MB, cached) has downloaded, the server runs the model instead.

### `intervention`: Intervention

- **What it is:** Clamps the pinned feature (−1× reverses it, ×0 removes it, ×2 amplifies it) and re-runs the real model from that step on, with every nonlinearity and the model’s own hint feedback recomputed.
- **Why it is there:** An attribution graph is a hypothesis about causes. The paper validates it by perturbing features and checking the prediction moves as the graph predicts; this does the same.
- **Technical note:** “Δ graph” = (factor − 1) × activation × total effect; “Δ actual” = what the real network did. The count of flipped ReLU / max-routing decisions tells you how far outside the frozen-linear regime the perturbation went.

### `ivDbl`: ×2 — amplify

- **What it is:** Doubles the feature’s activation and re-runs the real model.
- **Why it is there:** The opposite test to ablation: the prediction should move the other way.

### `ivNeg`: −1× — invert

- **What it is:** Reverses the feature’s activation and re-runs the real model.
- **Why it is there:** A stronger perturbation than ablation; the paper uses negative multiples to make effects easier to see.

### `ivZero`: ×0 — ablate

- **What it is:** Sets the feature’s activation to zero and re-runs the real model.
- **Why it is there:** Tests necessity: does the prediction depend on this feature?

### `leafMsg`: msg@t:j — message leaf

- **What it is:** The aggregated message node j received at step t: a max over all other nodes of the message MLP.
- **Why it is there:** Bundling it as a leaf keeps the graph per-node. It means influence from neighbours is shown as one input rather than traced node by node.
- **Technical note:** A limitation of this tool versus the paper, which traces through attention to other token positions.

### `leafNodeFts`: node_fts@t:j — input leaf

- **What it is:** The encoded inputs and hints of node j at step t (position, source flag, the previous hint values…), after CLRS’s linear encoders.
- **Why it is there:** Leaves are where the explanation stops: they are observed data, not computed features.

### `legendCat`: Categorical-class feature

- **What it is:** A feature labelled by a class transition of a categorical hint (e.g. becomes class 1 = turns grey in DFS). Tinted with that class’s colour.

### `legendLeaf`: Leaf / bias

- **What it is:** Grey boxes are inputs to the explanation (node_fts, msg) or the constant bias.

### `legendNeg`: Negative edge

- **What it is:** Red: the source pushes the destination down (away from the predicted value / class).

### `legendPos`: Positive edge

- **What it is:** Blue: the source pushes the destination up (toward the predicted value / class).

### `legendReach`: Reach/state feature

- **What it is:** A feature whose best label is a state predicate of the target hint (e.g. newly reached, stays reached, distance decreases).

### `legendSource`: Source feature

- **What it is:** A feature labelled as tracking whether a node is the source.
- **Why it is there:** Many algorithms start from the source, so the model needs a stable “I am the source” signal.

### `legendUnlabeled`: Unlabeled / rare

- **What it is:** No predicate describes this feature well, or it fires too rarely to name. It can still carry real influence.
- **Why it is there:** The paper also finds many features that resist a clean label; they are shown, not hidden.

### `minw`: min |w|

- **What it is:** Hides edges whose |weight| is below this absolute value.
- **Why it is there:** A quick way to look at only the dominant paths.

### `n`: n — number of nodes

- **What it is:** Size of the random graph sampled by CLRS’s own sampler (4–32 here). The checkpoints were trained on CLRS’s default mix of 4, 7, 11, 13 and 16-node graphs, validated on 16 and tested on 64.
- **Why it is there:** Going above 16 probes out-of-distribution size generalisation, which is exactly what the CLRS benchmark tests.
- **Technical note:** Changes apply immediately; neighbouring values are pre-computed in the background.

### `new`: New random graph

- **What it is:** Samples a fresh graph and runs the real trained model on it.
- **Why it is there:** A circuit seen on one graph is only a hypothesis; checking it on many graphs is how you find out whether it generalises (Figure 4 vs Figure 7 in this project).
- **Technical note:** Two or three next graphs are always pre-computed, so this is usually instant.

### `p`: p — edge probability

- **What it is:** Each possible edge is included independently with probability p: an Erdős–Rényi random graph, directed/acyclic/weighted as the algorithm requires (CLRS samplers). Training drew p from 0.1–0.9 (halved for articulation points, bridges and Kruskal).
- **Why it is there:** Sparse graphs give long, chain-like executions; dense graphs finish in few steps. The circuits used can differ between the two.
- **Technical note:** Changes apply immediately.

### `play`: Play / Pause

- **What it is:** Advances one algorithm step every 1.6 s and re-traces the attribution graph for the selected node at each step.
- **Why it is there:** Watching the same node over time shows which features switch on as the algorithm progresses (e.g. a “frontier” feature right before a node becomes reached).
- **Technical note:** Changing the graph, n, p, seed or algorithm stops playback immediately.

### `precision`: Precision (P)

- **What it is:** Of all the sites (node, step) where the feature fires, the fraction where the predicate is true.
- **Why it is there:** High P means that when the feature is on, the label is almost always correct.

### `pruned`: Pruned

- **What it is:** Keeps the nodes carrying 80% of the influence on the predictions (influence = probability-weighted share of all paths into the targets), then the edges carrying 98% of the influence among them — the pruning rule of the Circuit Tracing paper.
- **Why it is there:** Full graphs have thousands of edges; pruning leaves the few paths that carry most of the effect.
- **Technical note:** The statistic below the graph reports how much influence the pruned graph keeps.

### `recall`: Recall (R)

- **What it is:** Of all the sites where the predicate is true, the fraction where the feature fires.
- **Why it is there:** High R means the feature catches almost every case of the concept. Features can be precise but partial (one of several features covering a concept).

### `seed`: seed

- **What it is:** Random seed for the graph sampler. Same (algorithm, n, p, seed) always gives the same graph, so any finding can be reproduced.
- **Why it is there:** If a sampled graph is degenerate (fewer than 3 algorithm steps), the seed is shifted automatically and the used seed is shown.
- **Technical note:** Use the spinner arrows to step through graphs; ±1 is pre-computed.

### `simulation`: Simulation

- **What it is:** The sampled graph at the selected algorithm step, coloured by the ground-truth hint for that step (from CLRS’s reference implementation).
- **Why it is there:** This is the “input and context” side: you pick a node and a step here, and the attribution graph explains the model’s prediction for that node at the next step.
- **Technical note:** Orange ring = source node (for algorithms that have one).

### `step`: Algorithm step

- **What it is:** CLRS records the textbook algorithm’s state after every step (the hints). The model runs one message-passing step per hint step, predicting step t+1 from step t.
- **Why it is there:** Attributions are computed per step because the same processor is reused, so “which step” plays the role that “which layer” plays in a transformer.

### `supernodes`: Supernodes

- **What it is:** Features that share the same human label are merged into one box, and their edges are summed.
- **Why it is there:** The paper groups related features into “supernodes” by hand to make a graph readable. Here the grouping is automatic, by the predicate that best describes each feature.
- **Technical note:** Aggregation only: the numbers are exact sums of the underlying edges.

### `target`: Target

- **What it is:** The hint this tool explains for the selected algorithm, with its type.
- **Why it is there:** The paper explains one output token at a time; here the “token” is one node’s hint value at the next step.

### `transcoder`: Transcoder

- **What it is:** A sparse dictionary (F = 192 features, at most K = 8 active) trained to read the node-update input (256 numbers: this node’s encoded inputs + previous state; plus 128 numbers of incoming messages) and reproduce the 128-number new state.
- **Why it is there:** The raw state is dense and entangled. Forcing it through a few active features makes each feature carry a specific, nameable meaning.
- **Technical note:** The paper uses cross-layer transcoders across a deep transformer. This MPNN has one processor reused each step, so one transcoder per algorithm plays the same role.

### `valtest`: val / test score (OOD)

- **What it is:** CLRS’s output score for this checkpoint (accuracy for pointer and categorical outputs, F1 for mask outputs): validation on 16-node graphs, test on 64-node graphs (the standard CLRS out-of-distribution split), as recorded by the training run.
- **Why it is there:** The gap is the most informative number here: it says whether the circuits below are an algorithm or a memorised pattern.
- **Technical note:** Re-scoring the checkpoints on fresh graphs reproduces these numbers (see the verification report in the repository).

## Entries that differ on the main page (edge-site transcoders)

### `attrgraph`: Attribution graph

- **What it is:** A graph of direct linear effects that explains one prediction. Columns are the receiving nodes, rows are algorithm steps (newest at the top). Each step has a row of transcoder latents (circles, 8 per sender → receiver pair) and a row of encoder leaves (squares: the inputs and fed-back hints read at that step). The window covers the last 3 steps; older state enters as one leaf per node.
- **Why it is there:** This is the method of Ameisen et al., “Circuit Tracing: Revealing Computational Graphs in Language Models”, Anthropic 2025, used in Lindsey et al., “On the Biology of a Large Language Model”, Anthropic 2025 to trace multi-step reasoning. Here it is applied to a graph neural network executing a textbook algorithm.
- **Technical note:** To make the model linear for one input, the max-routing winners, the LayerNorm σ and the ReLU pattern of the node update are frozen at their real values, and every pair has an error node. Edge = source activation × (its decoder vector · the gradient of the destination).

### `avAct`: Activation

- **What it is:** The latent’s value on this pair and step (after ReLU and top-k).

### `avError`: Error node

- **What it is:** The part of a pair’s message y that the transcoder did not reconstruct. Adding it back makes the replacement model reproduce the real network exactly (Circuit Tracing).
- **Why it is there:** Its outgoing weight shows how much of the mechanism lies outside the latents.

### `avRowF`: Latents at this step

- **What it is:** For every receiver node (column), the transcoder latents active on the pairs sender → receiver in this step (8 per pair, all senders), coloured by what the pair is in this graph: a real edge, a non-edge or a self pair. The hatched square is the error node of a pair. Label: sender : latent.
- **Why it is there:** Latents are the units this explanation is written in. They have no names yet.
- **Technical note:** Size ∝ √activation.

### `avRowL`: Leaves at this step

- **What it is:** The values the encoders read at this step: inputs (pos, A, adj, s…) and hints the model fed back from its previous prediction, per node; edge-located values (A[i,j]) sit under the sender. The earlier-state leaf is the hidden state from before the window.
- **Why it is there:** Leaves are where the explanation stops.

### `avTotalEffect`: Total effect

- **What it is:** Change in each target logit per unit change of this latent’s activation, summed over every path in the frozen-linear graph (direct, skip and indirect). Checked against finite differences in the test suite.
- **Why it is there:** The intervention panel compares this prediction with the real model.

### `avg_pe`: Latent on a real edge

- **What it is:** The pair sender → receiver is an edge of the input graph (adj > 0). Colour says what the pair is in this graph, not what the latent means.

### `avg_pn`: Latent on a non-edge pair

- **What it is:** The pair is not an edge of the input graph. The MPNN still computes a message for it (it uses an all-ones adjacency), so every pair has latents.

### `avg_ps`: Latent on a self pair

- **What it is:** Sender and receiver are the same node.

### `bias`: bias

- **What it is:** All constant terms on the frozen path (encoder, message-site, node-update, hidden-state-decoder and transcoder biases and offsets).
- **Why it is there:** Included so the edges into a node add up exactly to its value; the page checks that for every node.

### `bymeaning`: By meaning

- **What it is:** All latents that were found to mean the same thing (for example “frontier”) at one step are merged into one box, and their edges are summed. Latents without a name go into “unnamed”.
- **Why it is there:** Shows which kinds of message carry the computation. Names are only given to latents whose match holds up on graphs they were not fitted on.
- **Technical note:** Aggregation only: the numbers are exact sums; edges between latents of the same box are dropped.

### `bynode`: By node

- **What it is:** Every latent appears once per pair and step where it is active: column = receiving node, row = step. Its label is sender : latent index.
- **Why it is there:** Keeps full detail: you see exactly when and on which pair each latent fired.

### `demoLink`: Previous demo

- **What it is:** The earlier version of this tool, kept as it was: attribution graphs built from the node-site transcoder, with labelled features, top-activating examples and the node table.

### `etcDead`: Dead latents and sparsity

- **What it is:** Latents that never fire on the training rows, and the average number of active latents per pair (at most k).
- **Why it is there:** Dead latents are simply unused dictionary entries.

### `etcFlips`: Winner flips

- **What it is:** How often the replacement changes which sender wins a channel of the max when it runs on its own. A flip needs twice the reconstruction error to exceed the gap between the best and second-best sender; that bound was checked with zero violations.
- **Why it is there:** The attribution graph uses the real winners, so it is not affected.

### `etcFvu`: Reconstruction error (FVU)

- **What it is:** Fraction of the message variance the latents do not rebuild: on validation graphs (16 nodes), on the training rows, and on 64-node test graphs (measured for tier A only). 0 is perfect.
- **Why it is there:** The error node carries the rest, so the graph is exact for the real run whatever the FVU.

### `etcHid`: One-step hidden-state error

- **What it is:** Relative error of the next hidden state when one step’s messages are replaced, starting from the true input; mean over steps.

### `etcPanel`: Model & edge-site transcoder

- **What it is:** The trained MPNN for this algorithm and the measured quality of its edge-site transcoder, copied from the training run’s report.

### `etcRet`: Replacement fidelity

- **What it is:** The share of the original network’s score that is kept when the transcoder replaces the message MLP at every step and everything downstream is recomputed (winners included). “x of y” is the replaced score of the original score; a share above 100% can happen by chance.
- **Why it is there:** This measures whether the sparse code is a faithful stand-in for the real computation.

### `etcSite`: Transcoder site

- **What it is:** It reads the message input s of every sender → receiver pair and rebuilds the message y. D latents, of which k are active for each pair.

### `etcStep`: Error by step

- **What it is:** Reconstruction error of the messages at each algorithm step on validation graphs. Later steps are usually harder.

### `etcTier`: Tier

- **What it is:** A: the baseline MPNN generalises to 64 nodes (OOD F1 ≥ 0.90), so the replacement is judged at 16 and 64 nodes. B: it generalises badly, so the replacement is judged at 16 nodes only. C: the baseline itself is weak (validation F1 below 0.95): results are indicative only.

### `etcTrain`: Training

- **What it is:** Optimisation steps, number of pair rows used, and minutes of training for this algorithm’s edge-site transcoder.

### `featdetail`: Latent detail

- **What it is:** What is known about the clicked latent: its pair, activation, influence, where else it fires in this graph, its total effect on the targets and its edges.
- **Why it is there:** The latents have no names yet, so only facts measured on this graph are shown.

### `howItWorks`: How this tool works

- **What it is:** 1) CLRS samples a graph and runs the textbook algorithm to get hints. 2) The trained MPNN executes the same algorithm step by step; every ordered pair of nodes sends a message. 3) A transcoder rewrites each message as a few sparse latents. 4) Freezing the max-routing winners, the LayerNorm σ and the ReLU pattern makes one prediction a linear sum, shown as an attribution graph. 5) Clamping latents tests whether the graph is causally right.
- **Why it is there:** Accuracy says whether the model is right; this says how it gets there, and interventions say whether that story is true.
- **Technical note:** Method: Ameisen et al., “Circuit Tracing: Revealing Computational Graphs in Language Models”, Anthropic 2025 / Lindsey et al., “On the Biology of a Large Language Model”, Anthropic 2025. Benchmark: Veličković et al., “The CLRS Algorithmic Reasoning Benchmark”, ICML 2022.

### `intervention`: Intervention

- **What it is:** Clamps the pinned latent (−1× reverses it, ×0 removes it, ×2 amplifies it): the message of its pair changes by (factor − 1) × activation × decoder vector, and the real model is re-run from that step on with every nonlinearity and its own hint feedback recomputed.
- **Why it is there:** An attribution graph is a hypothesis about causes; clamping tests it.
- **Technical note:** “Δ graph” = (factor − 1) × activation × total effect; “Δ actual” = what the real network did. The graph freezes σ, winners and TopK sets, so in our tests its predicted direction matched the real model 69% of the time (44–77% depending on the algorithm).

### `ivDbl`: ×2 — amplify

- **What it is:** Doubles the latent’s activation and re-runs the real model.
- **Why it is there:** The opposite test to ablation.

### `ivNeg`: −1× — invert

- **What it is:** Reverses the latent’s activation and re-runs the real model.
- **Why it is there:** A stronger perturbation than ablation.

### `ivZero`: ×0 — ablate

- **What it is:** Sets the latent’s activation to zero and re-runs the real model.
- **Why it is there:** Tests necessity: does the prediction depend on this latent?

### `latDict`: Latent dictionary

- **What it is:** The latents of this algorithm that can be named, with the evidence: precision, recall and F1 of the condition on graphs that were not used to pick it (tier A: F1 ≥ 0.8, tier B: F1 ≥ 0.5), how often the latent fires, and its average effect on the receiver’s prediction.
- **Why it is there:** Most latents have no simple description; those are left unnamed on purpose rather than guessed.
- **Technical note:** Measured on 60 fresh graphs per algorithm, 30 to choose the condition and 30 to score it.

### `supernodes`: Supernodes

- **What it is:** All latents of one sender → receiver pair at one step are merged into one box, and their edges are summed.
- **Why it is there:** Shows which messages (which sender to which receiver) carry the computation.
- **Technical note:** Aggregation only: the numbers are exact sums of the underlying edges; edges between latents of the same box are dropped.

### `topLatents`: Top latents at each step

- **What it is:** For every step in the window, the six latents of the pruned graph with the most influence on the predictions: the pair they sit on, their activation, what they were found to mean and what they do to the receiver. Click a row to pin the latent.
- **Why it is there:** Step by step, this is the short list of what mattered.

### `transcoder`: Edge-site transcoder

- **What it is:** A sparse dictionary (D = 1,280 latents, at most k = 8 active) trained to read the message input of one sender → receiver pair (128 numbers: the summed, pre-ReLU message) and reproduce the 128-number message the message MLP outputs.
- **Why it is there:** The raw message is dense and entangled; forcing it through a few active latents is what lets a circuit be read.
- **Technical note:** The MPNN has one processor reused at every step, so one transcoder per algorithm covers all steps. It was trained on the real activations of that algorithm’s MPNN.
