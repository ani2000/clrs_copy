## Breadth-first search (`bfs`)

### What it computes

Starting from a source node s, BFS visits the graph in rings: first s, then every node one edge away, then every node two edges away, and so on.
The result is a tree of parent pointers (pi): every reached node points to the node it was first reached from.
It runs in O(V + E) time on an adjacency list.

### What the network has to learn

The model has to learn a simple rule: "a node becomes reached when some already-reached node has an edge to it". Each message-passing step it executes one ring of the search.

In one line: The easiest of the twelve: the model keeps 99.8% accuracy on graphs four times bigger than it was trained on.

## Depth-first search (`dfs`)

### What it computes

DFS explores as deep as possible along each path before backing up. It colours nodes white (not seen), gray (being explored) and black (finished) and records discovery and finishing times.
The order in which nodes are finished is the basis of topological sorting and of strongly connected components.
It runs in O(V + E) time.

### What the network has to learn

The model has to keep an implicit stack: which node is currently being explored and which neighbours are still unvisited. The target the site explains is the colour of each node.

In one line: Perfect on the training size, but the stack depth seems tied to 16 nodes: on 64-node graphs it keeps only 48% (SEVERE).

## Bellman-Ford shortest paths (`bellman_ford`)

### What it computes

Computes the shortest distance from a source to every node, even when edge weights are negative. It repeats "relax every edge" |V| - 1 times: if going through edge (u, v) gives a shorter path to v, update d[v] and the parent pointer.
It runs in O(V * E) time.

### What the network has to learn

Each message-passing step is one round of relaxation over all edges, which is exactly what a max-aggregating message-passing layer can express. The site explains the distance d.

In one line: Generalises well (94.8% on 64 nodes, CLEAN).

## Dijkstra shortest paths (`dijkstra`)

### What it computes

Computes shortest distances from a source when all weights are non-negative. It keeps a priority queue of unfinished nodes, repeatedly extracts the closest one, marks it finished and relaxes its outgoing edges.
It runs in O((V + E) log V) with a binary heap.

### What the network has to learn

The model has to find the closest unfinished node each step (an arg-min over nodes) and update its neighbours. The site explains the distance d.

In one line: CLEAN: 97.7% on 64 nodes. One of the two algorithms (with Prim) where the transcoder-in-the-network agreement is lowest on this site.

## Kruskal minimum spanning tree (`mst_kruskal`)

## Articulation points (cut vertices) (`articulation_points`)

### What it computes

A cut vertex is a node whose removal disconnects the graph. It is found with one DFS that tracks, for each node, the lowest discovery time reachable from its subtree ("low").
The root is a cut vertex if it has two or more DFS children; any other node u is one if some child v has low[v] >= d[u].
It runs in O(V + E).

### What the network has to learn

The model has to simulate DFS and the low-link bookkeeping. The site explains the "is a cut vertex" mask.

In one line: CLEAN: 94.9% on 64 nodes.

## Strongly connected components (`strongly_connected_components`)

### What it computes

Two nodes are in the same strongly connected component if each can reach the other. The classical algorithm runs DFS, reverses all edges, and runs DFS again in decreasing finishing time; every tree of the second search is one component.
It runs in O(V + E).

### What the network has to learn

The model has to run two DFS passes with a graph reversal in between. The site explains the DFS colour of each node.

In one line: SEVERE and the largest gap of all: 27.3% on 64 nodes.

### The pseudo-code the site shows

The line numbers are the ones used by the highlighting. Indentation shows nesting; the colours on the page show the depth of the line.

```text
  1  SCC(G)
  2    for each vertex u:  color[u] ← WHITE
  3    for each vertex u                       // pass 1 on G
  4      if color[u] = WHITE
  5        DFS-VISIT(G, u)
  6    Gᵀ ← G with every edge reversed
  7    for each vertex u:  color[u] ← WHITE
  8    for each u, in decreasing order of f[u]  // pass 2 on Gᵀ
  9      if color[u] = WHITE
 10        comp ← new empty component
 11        DFS-VISIT(Gᵀ, u), adding every vertex it reaches to comp
 12    return the components
 13  DFS-VISIT(H, u)
 14    color[u] ← GRAY
 15    for each v in Adj_H[u]
 16      if color[v] = WHITE
 17        DFS-VISIT(H, v)
 18    color[u] ← BLACK
 19    f[u] ← ++time                           // pass 1 only
```

## Floyd-Warshall all-pairs shortest paths (`floyd_warshall`)

### What it computes

Computes the shortest distance between every pair of nodes. For each intermediate node k in turn, it checks whether going i -> k -> j beats the best known i -> j.
It runs in O(V^3) time; the three nested loops are k (outer), i and j.

### What the network has to learn

The model keeps an N x N table of distances and has to apply the k-th relaxation to all pairs at once. The site explains the mask that marks the current k.

In one line: SEVERE and tier C: only 93.1% validation and 38.5% on 64 nodes.

### The CLRS fields the network reads

The model bundle (`models/<algo>.json`, written by `model_export.py`) lists every input and hint field with its location and type. Output-stage fields are not exported because the browser only needs the hints.

| field | stage | location | type | width (K) | meaning of the columns |
|---|---|---|---|---|---|
| `pos` | input | node | scalar | 1 | node = one value per node; edge = one per ordered pair; graph = one for the whole graph |
| `A` | input | edge | scalar | 1 |  |
| `adj` | input | edge | mask | 1 |  |
| `Pi` | output | edge | pointer |  |  |
| `Pi_h` | hint | edge | pointer | 1 |  |
| `D` | hint | edge | scalar | 1 |  |
| `msk` | hint | edge | mask | 1 |  |
| `k` | hint | node | mask_one | 1 |  |

Counting both stages, the network encodes 8 fields; the processor weights, the encoders and the hint decoders together make 350,216 float32 numbers (1.40 MB), which is the size of `models/floyd_warshall.bin`.

### The target the site explains

- target hint: `k` (mask_one), stage `hint`
- this algorithm has no source node
- a mask_one holds exactly one true node per step (a softmax over nodes).

### The pseudo-code the site shows

The line numbers are the ones used by the highlighting. Indentation shows nesting; the colours on the page show the depth of the line.

```text
  1  FLOYD-WARSHALL(W)
  2    n ← rows(W);   D ← W
  3    for k ← 1 to n
  4      for i ← 1 to n
  5        for j ← 1 to n
  6          D[i][j] ← min(D[i][j],  D[i][k] + D[k][j])
```
